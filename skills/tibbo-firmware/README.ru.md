# tibbo-firmware

[English](README.md) · **Русский** · [← Все скиллы](../../README.ru.md)

Скилл для ИИ-агентов (Claude, Codex, Gemini CLI, Kimi Code, Deep Code и других) - **прошивки и аппаратной конфигурации Tibbo**: приложения TiOS на Tibbo BASIC и Tibbo C,
библиотеки Tibbo, подбор Tibbit, раскладка по сокетам TPS и проверка питания.

<img src="../../docs/images/tps-board-tpp3.svg" alt="Проверка платы TPS" width="720" />

## Что умеет

| Задача | Как скилл её решает |
|---|---|
| **Написать прошивку** | Фиксирует допущения (платформа, Tibbit, питание, язык), берёт за основу одну из 20 готовых программ или генератор проекта (`tibbo_new.py`: библиотеки с зависимостями, вызовами в событиях и callback-ами), проверяет код по точному API платформы (`tibbo_lint.py`) и **собирает его компилятором Tibbo** (`tibbo_build.py`), пока не останется ошибок. Результат - проект TIDE (`.tpr`, `global.tbh`, `main.tbs`, `device.tbs`, `settings.txt`) и таблица ресурсов (сокеты, UART, линии ввода-вывода, страницы буферов). |
| **Собрать и загрузить** | Собирает компилятором Tibbo на Node.js (любая ОС), вашей TIDE или - с вашего согласия - в облаке Tibbo; объясняет каждую ошибку компилятора и компоновщика; находит устройства в сети, загружает и запускает прошивку через tide-proxy Tibbo (экспериментально). Говорит, что настроить именно в вашем случае. |
| **Проверить прошивку** | Проходит чек-лист из 34 пунктов: язык и память, событийная модель, ресурсы, сеть, библиотеки, железо, питание, хранение и надёжность. Находки делит на «критично / важно / замечание» с файлом, процедурой и исправленным фрагментом. |
| **Найти причину по симптому** | Устройство зависает, библиотека не работает, сокет не принимает подключения, данные обрезаются, плата перезагружается при включении реле, АЦП показывает ноль, TLS не устанавливается - для каждого случая типичные причины. |
| **Подобрать Tibbit** | Ищет по каталогу из 84 Tibbit, раскладывает по процедуре (тайлы и формы M/C/H, сокеты UART/INT/ADC/PoE) и проверяет результат скриптом `tps_check.py`. |
| **Проверить питание** | Источники #09/#10/#25/#33/#23/#12, диапазоны входа, ±15 В, PoE, потребление плат, допустимая загрузка с модемом и при нагреве. Числа в ответе берутся из вывода скрипта, а не из памяти. |
| **Linux-платы** | LTPP3(G2): Tibbit, слоты и питание проверяются как на TPS; программа - приложение Linux (Python, C, Node.js), а не Tibbo BASIC - скилл прямо это говорит и даёт первые шаги по документации Tibbo. |
| **Нарисовать** | Плату TPS как в конфигураторе Tibbo и диаграмму состояний прошивки, построенной как конечный автомат. |

Проекты TIDE, сгенерированные AppBlocks, распознаются (`APP_ID`, маркеры `'****boot****'`, процедуры `var_<X>_update`):
скилл проверяет их как обычный проект, но советует вносить правки в сам проект AppBlocks, чтобы они не пропали
при следующей генерации.

## Инструменты

Все скрипты используют только стандартную библиотеку Python. Для сборки и работы с устройствами дополнительно нужны
Node.js 18+ и git (или TIDE на Windows); компилятор Tibbo и tide-proxy агент ставит только после вашего «да».

### `tps_check.py`

```bash
python3 scripts/tps_check.py check cfg.json [--json] [--svg board.svg]   # проверить конфигурацию TPS
python3 scripts/tps_check.py find "rs485 modbus"                         # поиск по каталогу Tibbit
python3 scripts/tps_check.py board "TPP3W(G2)"                           # сокеты и PL_IO_NUM_* платы
python3 scripts/tps_check.py tibbit 25                                   # всё об одном Tibbit
```

Коды выхода: `0` - ошибок нет, `1` - найдены ошибки, `2` - неверные входные данные.

Формат конфигурации:

```jsonc
{
  "board": "TPP3W(G2)",          // TPP2W, TPP2W(G2), TPP2W(G3), TPP2N, TPP3W, TPP3W(G2), TPP3W(G3), TPP3N
  "slots": {"S1": "05", "S2": "21", "S9": "25", "S10": "18", "S25": "23"},
                                 // широкий Tibbit указывается один раз, в первом сокете;
                                 // параметры сокета: "S9": {"model": "25", "vin": 24}
  "power": {"vin": 24,           // напряжение на входе Tibbit-источников, В
            "ext5v_ma": 0},      // внешний стабилизированный БП 5 В на клеммах, мА (0 - нет)
  "poe_jumpers": "2-3",          // "1-2" - питание с RJ45 заведено на PoE-сокет
  "wifi": null,                  // "WA2000", если стоит Wi-Fi-модуль
  "buzzer": true,
  "ambient_c": 40,               // максимальная температура в корпусе, °C
  "extra_5v_ma": 0               // прочие потребители на шине 5 В
}
```

Что проверяется: форма и занятость сокетов, конфликты линий, требования UART и прерываний, разъёмы рядом
с Tibbit, которым они нужны, PoE-сокет и перемычки, входное напряжение каждого источника, ±15 В для #13/#14,
бюджет +5 В с запасом для модема и с учётом температуры.
В SVG - плата, таблица «Подключение к CPU», полоса бюджета питания и пронумерованные ошибки.

### `tibbo_new.py`

```bash
python3 scripts/tibbo_new.py my_app --platform "TPP3W(G2)" --libs dhcp,settings,mqtt
python3 scripts/tibbo_new.py --list              # библиотеки и что каждая тянет за собой
python3 scripts/tibbo_new.py --list-platforms
```

Создаёт проект, который собирается сразу: `.tpr` (файлы библиотек с `location = commonlib`, `src_lib_ver`, `defines=`
для выключенных по умолчанию объектов), `global.tbh`, `main.tbs` с вызовами всех библиотек в нужных событиях и
`device.tbs` со всеми обязательными callback-ами. Зависимости подтягиваются сами (dhcp → wln там, где у платформы есть
Wi-Fi; mqtt → sock + dns; tables → filenum + time). Проверено сборкой на всех 28 платформах с 13 библиотеками. То, что
не соберётся (Linux-плата, mqtt на старых платформах), генератор не создаёт и объясняет причину.

### `tibbo_lint.py`

```bash
python3 scripts/tibbo_lint.py my_project/          # платформа и список файлов берутся из .tpr
python3 scripts/tibbo_lint.py main.tbs --platform "TPP3W(G2)" [--json]
```

Ловит типичные ошибки нейросетей раньше компилятора:

- свойство, метод, константа или объект, которых нет **на выбранной платформе** (`sock.conect` → «похоже:
  `sock.connect`»), запись в свойство только для чтения, не то число аргументов, выключенный объект (и строка
  `defines=`, которая его включает);
- **выдуманное имя события** (`on_button_press`): компилятор его молча пропускает, а обработчик никогда не
  вызывается; неверная сигнатура события, один обработчик дважды, прямой вызов обработчика;
- правила Tibbo BASIC: `elseif`, рекурсия, `string(300)`, `return`, `print`, `sleep`, `+=`, `!=`, `&&`, `&` для
  строк, типы из других языков;
- не написан обязательный callback подключённой библиотеки (иначе - ошибка компоновщика).

Из 23 ошибок, о которых сообщает компилятор Tibbo, линтер находит 20 до сборки, а ещё - выдуманные события, о которых
компилятор не сообщает вовсе; на 15 проектах с github.com/tibbotech - ни одной ложной ошибки. Коды выхода: `0` -
ошибок нет, `1` - есть ошибки, `2` - неверные входные данные. Линтер не заменяет компилятор: типы и выражения
проверяет `tibbo_build.py`.

### `tibbo_build.py`

```bash
python3 scripts/tibbo_build.py --doctor [my_project]      # что работает на этом компьютере и что сделать вам
python3 scripts/tibbo_build.py --setup-node --yes         # поставить компилятор Tibbo (Node.js 18+, git; один раз)
python3 scripts/tibbo_build.py my_project [--json]        # проверить код: ошибки вида файл(строка) текст + «что делать»
python3 scripts/tibbo_build.py my_project --release --out app.tpc    # прошивка для устройства
```

Три способа, выбор - по цели: проверка кода - компилятор Tibbo на Node.js (любая ОС, Tibbo BASIC, код не покидает
компьютер); прошивка для устройства - ваша TIDE (`tmake`), если она установлена; облачный сборщик Tibbo - запасной
путь (Tibbo C без TIDE), только с ключом `--cloud-ok` после согласия пользователя: проект уходит на сервер Tibbo.
Перед сборкой проверяется `.tpr`; под каждой ошибкой - строка «что делать». На 15 проектах tibbotech компилятор на
Node.js дал побайтно те же `.tpc` и те же ошибки, что облачный.

### `tibbo_device.py` (экспериментально)

```bash
python3 scripts/tibbo_device.py --setup --yes     # поставить tide-proxy Tibbo (Node.js; один раз)
python3 scripts/tibbo_device.py list              # устройства в локальной сети
python3 scripts/tibbo_device.py upload app.tpc --mac 0.36.119.87.32.2 --yes --run
```

`list`, `state` и `buzz` безопасны; `upload`, `run`, `stop`, `reboot` требуют `--yes`; саму TiOS скрипт не заменяет
без `--allow-tios`. Проверено на заменителе, говорящем по протоколу Tibbo; на реальном устройстве - ещё нет.

## Ограничения

- **Прошивки - только для TiOS.** Для Linux-плат (LTPP3(G2), LTPP3) скилл проверяет железо и даёт первые шаги (`references/linux.md`), но не пишет код на Tibbo BASIC.
- **Сборка без ошибок - ещё не проверка.** Компилятор проверяет язык, а не логику и не железо: пробуйте прошивку на устройстве. Там, где агент не может запускать скрипты (веб-чат), ничего не собирается, и ответ прямо об этом говорит.
- **Компилятор на Node.js собирает только Tibbo BASIC** и берёт файлы платформ своего выпуска (платформы G3 - как TiOS 4.01, если не ставить с `--latest-platforms`). Для Tibbo C нужна TIDE или облачная сборка. Отладка по шагам остаётся в TIDE.
- **`tmake`, `tupload` и `tibbo_device.py` на реальном железе не запускались** - только на заменителях, повторяющих командную строку и протокол Tibbo.
- **`tps_check.py` - только для плат TPS.** Модули DS/EM/WM проверяются вручную по `power.md` и даташиту модуля, и в ответе это указывается.
- **Снимок данных на ноябрь 2026.** Если чего-то нет, агент читает страницу на docs.tibbo.com или исходник на github.com/tibbotech.
