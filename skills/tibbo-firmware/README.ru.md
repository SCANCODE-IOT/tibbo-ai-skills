# tibbo-firmware

[English](README.md) · **Русский** · [← Все скиллы](../../README.ru.md)

Скилл для ИИ-агентов (Claude, Codex, Gemini CLI, Kimi Code, Deep Code и других) - **прошивки и аппаратной конфигурации Tibbo**: приложения TiOS на Tibbo BASIC и Tibbo C,
библиотеки Tibbo, подбор Tibbit, раскладка по сокетам TPS и проверка питания.

<img src="../../docs/images/tps-board-tpp3.svg" alt="Проверка платы TPS" width="720" />

## Что умеет

| Задача | Как скилл её решает |
|---|---|
| **Написать прошивку** | Фиксирует допущения (платформа, Tibbit, питание, язык, версия библиотек), сверяет каждое имя объекта, константы и библиотечной процедуры со справочниками, выдаёт проект TIDE файлами (`global.tbh`, `main.tbs`, `device.tbs`, `settings.txt`, `.tpr`) и таблицу ресурсов (сокеты, UART, линии I/O, страницы буферов). |
| **Проверить прошивку** | Проходит чек-лист из 34 пунктов: язык и память, событийная модель, ресурсы, сеть, библиотеки, железо, питание, хранение и надёжность. Находки делит на «критично / важно / замечание» с файлом, процедурой и исправленным фрагментом. |
| **Найти причину по симптому** | Устройство зависает, библиотека не работает, сокет не принимает подключения, данные обрезаются, плата перезагружается при включении реле, АЦП показывает ноль, TLS не устанавливается - для каждого случая типичные причины. |
| **Подобрать Tibbit** | Ищет по каталогу из 84 Tibbit, раскладывает по процедуре (тайлы и формы M/C/H, сокеты UART/INT/ADC/PoE) и проверяет результат скриптом `tps_check.py`. |
| **Проверить питание** | Источники #09/#10/#25/#33/#23/#12, диапазоны входа, ±15 В, PoE, потребление плат, допустимая загрузка с модемом и при нагреве. Числа в ответе берутся из вывода скрипта, а не из памяти. |
| **Нарисовать** | Плату TPS как в конфигураторе Tibbo и диаграмму состояний прошивки, построенной как конечный автомат. |

Проекты TIDE, сгенерированные AppBlocks, распознаются (`APP_ID`, маркеры `'****boot****'`, процедуры `var_<X>_update`):
скилл проверяет их как обычный проект, но советует вносить правки в сам проект AppBlocks, чтобы они не пропали
при следующей генерации.

## Инструменты

Все скрипты используют только стандартную библиотеку Python.

### `tps_check.py`

```bash
python3 scripts/tps_check.py check cfg.json [--json] [--svg board.svg]   # проверить конфигурацию TPS
python3 scripts/tps_check.py find "rs485 modbus"                         # поиск по каталогу Tibbit
python3 scripts/tps_check.py board "TPP3W(G2)"                           # сокеты и PL_IO_NUM_* платы
python3 scripts/tps_check.py tibbit 25                                   # всё об одном Tibbit
```

Коды выхода: `0` - ошибок нет, `1` - найдены ошибки, `2` - неверные входные данные.

Формат конфигурации:

```jsonc
{
  "board": "TPP3W(G2)",          // TPP2W, TPP2W(G2), TPP2W(G3), TPP2N, TPP3W, TPP3W(G2), TPP3W(G3), TPP3N
  "slots": {"S1": "05", "S2": "21", "S9": "25", "S10": "18", "S25": "23"},
                                 // широкий Tibbit указывается один раз, в первом сокете;
                                 // параметры сокета: "S9": {"model": "25", "vin": 24}
  "power": {"vin": 24,           // напряжение на входе Tibbit-источников, В
            "ext5v_ma": 0},      // внешний стабилизированный БП 5 В на клеммах, мА (0 - нет)
  "poe_jumpers": "2-3",          // "1-2" - питание с RJ45 заведено на PoE-сокет
  "wifi": null,                  // "WA2000", если стоит Wi-Fi-модуль
  "buzzer": true,
  "ambient_c": 40,               // максимальная температура в корпусе, °C
  "extra_5v_ma": 0               // прочие потребители на шине 5 В
}
```

Что проверяется: форма и занятость сокетов, конфликты линий, требования UART и прерываний, разъёмы рядом
с Tibbit, которым они нужны, PoE-сокет и перемычки, входное напряжение каждого источника, ±15 В для #13/#14,
бюджет +5 В с запасом для модема и с учётом температуры.
В SVG - плата, таблица «Подключение к CPU», полоса бюджета питания и пронумерованные ошибки.

### `state_diagram.py`

```bash
python3 scripts/state_diagram.py fsm.json fsm.svg
```

```json
{
  "title": "Автополив - конечный автомат (тик 0,5 с)",
  "states": [
    {"id": "START", "note": "8 замеров", "outputs": "насос выкл", "kind": "init"},
    {"id": "IDLE",  "note": "ждём сухость", "outputs": "насос выкл"},
    {"id": "WATER", "outputs": "насос вкл", "kind": "active"},
    {"id": "FAULT", "note": "насос заблокирован", "kind": "fault"}
  ],
  "transitions": [
    {"from": "START", "to": "IDLE", "label": "8 исправных замеров"},
    {"from": "IDLE", "to": "WATER", "label": "влажность < порога"},
    {"from": "*", "to": "FAULT", "label": "датчик вне диапазона"}
  ]
}
```

`kind`: `init` (синий), `normal` (зелёный, по умолчанию), `active` (оранжевый), `fault` (красный). `"from": "*"` - «из любого состояния».

### `tibbo_lint.py`

```bash
python3 scripts/tibbo_lint.py my_project/ --platform "TPP3W(G2)"   # .tbs .tbh .tc .th, папки целиком
python3 scripts/tibbo_lint.py main.tbs --json
```

Ловит выдуманные и опечатанные имена API раньше TIDE - это самая частая ошибка нейросетей:

- неизвестное свойство, метод или событие объекта TiOS (`sock.conect` → «похоже: `sock.connect`»);
- несуществующая константа `PL_*` (`PL_SSTS_CONECTED`, `PL_IO_NUM_99`);
- с `--platform`: объект или константа, которых нет на платформе (`adc` на TPP2W(G2)); ветки
  `#if PLATFORM_ID=…` для других платформ пропускаются;
- `elseif` (в Tibbo BASIC только `else if`).

Внутренние члены (в `.tph` со знаком `!`) дают предупреждение. Коды выхода: `0` - ошибок нет, `1` - есть ошибки,
`2` - неверные входные данные. Проверен на 1382 файлах библиотек и примеров самой Tibbo - ни одной ложной ошибки.
Процедуры библиотек (`dhcp_start`, `mqtt_publish`…) не проверяются - сверяйте их с `references/libraries.md`.

## Ограничения

- **Только TiOS.** Linux-устройства (LTPP3, LTPP3G2, NTIOS) работают на Linux с C/Node.js и другими объектами; скилл это отмечает и не смешивает два мира.
- **Нет компилятора.** TIDE нейросети недоступна, код проверяется статически. Скилл никогда не утверждает, что код «скомпилируется».
- **`tps_check.py` - только для плат TPS.** Модули DS/EM/WM проверяются вручную по `power.md` и даташиту модуля, и в ответе это указывается.
- **Снимок данных на октябрь 2026.** Если чего-то нет, агент читает страницу на docs.tibbo.com или исходник на github.com/tibbotech.
