# TIDE: сборка, загрузка, ошибки компилятора

Как собирать и загружать проекты Tibbo без ручной работы в окне TIDE и как читать ошибки компилятора.
Инструмент: `scripts/tibbo_build.py`. Данные о командной строке TIDE сняты с TIDE 2023 (tmake, tupload v5.04.50).

## 1. Что нужно от пользователя

TIDE работает только под Windows и только на компьютере пользователя. Получится ли у агента до него достать, зависит
не от модели, а от того, **где работает агент**. Поэтому порядок такой:

1. **Перед первой сборкой в разговоре** запусти `python3 scripts/tibbo_build.py --doctor` (или `--doctor --json`).
   Он определяет, где запущен (Windows, WSL, Linux/macOS, контейнер, песочница Gemini/Codex), находит TIDE и
   компилятор Tibbo на Node.js, проверяет связь с облачным компилятором и печатает **«Что сделать пользователю»**.
2. Если сборка возможна (в строке `Сборка будет` нет «НЕВОЗМОЖНА» для нужного случая) - собирай. Если нет - **одним сообщением** перескажи пользователю
   пункты «Что сделать» простыми словами и предложи варианты из таблицы ниже. Не проси того, чем не сможешь
   воспользоваться: доступ к папке TIDE бесполезен, если ты не можешь запускать на этом компьютере команды.
3. Скрипты запустить нельзя (веб-чат) - сразу переходи к варианту «пользователь собирает сам».

| Где работает агент | Локальный TIDE | Что сделать пользователю |
|---|---|---|
| **Агент в терминале или редакторе на том же Windows-компьютере, где TIDE** (Claude Code, Codex CLI, Gemini CLI, Kimi Code, OpenCode, Cline, Cursor, Copilot в VS Code) | да | Открыть агента в папке проекта. Разрешить запуск `python` (агент спросит; чтобы не спрашивал каждый раз - добавить команду в разрешённые в настройках агента). TIDE не в стандартной папке - переменная `TIDE_DIR`. Gemini CLI - без `--sandbox`. |
| **Агент в WSL** на Windows-компьютере с TIDE | да, экспериментально | Проект держать на диске Windows (`/mnt/c/...`). TIDE не на C: - `TIDE_DIR=/mnt/<диск>/...`. |
| **Агент на другом компьютере, в Linux/macOS, в контейнере или облачной песочнице** (Claude в браузере и приложениях, ChatGPT, приложение Kimi, Codex в облаке) | нет | Лучше всего - компилятор Tibbo на Node.js прямо там, где работает агент (Tibbo BASIC; нужны Node.js 18+ и git, установка один раз `--setup-node --yes` с согласия пользователя, сеть до github.com и registry.npmjs.org). Иначе: облачный компилятор Tibbo (согласие + доступ к `api.appblocks.io`), или собрать самому и прислать вывод, или запустить агента на Windows-компьютере с TIDE. Облачный агент, связанный с компьютером пользователя, может собрать локально, только если умеет **запускать команды** на этом компьютере (не только читать файлы). |
| **Веб-чат без запуска кода** (DeepSeek, GLM, Gemini и ChatGPT без инструментов) | нет | Собрать самому: Build → Rebuild All в TIDE (или команда `tibbo_build.py`) и вставить в чат вывод панели Output. Агент разбирает ошибки по §5. |

Сообщение пользователю, если локальной сборки нет (подставь пункты из `--doctor`):
> Чтобы проверить код компилятором Tibbo, есть такие пути:
> 1. Поставить здесь компилятор Tibbo на Node.js (скачаю с GitHub Tibbo около 200 МБ, около минуты) - дальше собираю
>    сам, код никуда не уходит. Подходит для Tibbo BASIC. Ставим?
> 2. Облачный компилятор Tibbo - собираю сам, но файлы проекта уйдут на сервер Tibbo (api.appblocks.io). Согласны?
> 3. Вы собираете в TIDE (Build → Rebuild All) и присылаете мне текст из окна Output - я исправлю ошибки.
> 4. Запустить меня на компьютере с TIDE (например, Claude Code или Codex в папке проекта) - тогда собираю и загружаю сам.
Предлагай только доступные пункты: нет Node.js и его не поставить - без пункта 1; нет сети до api.appblocks.io - без 2.

Что делает каждая возможность и что для неё нужно:

| Что хотим | Что нужно | Как проверить |
|---|---|---|
| Проверить код компилятором Tibbo | Локально: TIDE на Windows-компьютере, где работает агент. Или компилятор Tibbo на Node.js на любой ОС (Tibbo BASIC; Node.js 18+ и git, установка `--setup-node --yes` с согласия). Облако: интернет до `api.appblocks.io` и **согласие пользователя**. | `tibbo_build.py --doctor` |
| Получить готовый `.tpc` | То же, что выше. `--release` - для работы без TIDE. | `tibbo_build.py <проект> --release` |
| Найти устройство, загрузить `.tpc`, запустить | Компьютер в той же сети, что устройство: TIDE на Windows (`tupload`, ещё и COM-порт) или tide-proxy Tibbo на любой ОС (Node.js, `tibbo_device.py --setup --yes`, экспериментально). **Явное «да» пользователя** на каждую загрузку. Из облачной песочницы - нельзя. | `tibbo_device.py list`, `tibbo_build.py --upload app.tpc --target <адрес> --yes` |
| Отлаживать по шагам, смотреть переменные | Только в окне TIDE (Debug). Агент с управлением компьютером может работать в окне TIDE, остальные объясняют шаги. | - |

Настройки:
- `TIDE_DIR` - папка TIDE, если не `C:\Program Files (x86)\Tibbo\TIDE`. Задать в Windows: Параметры → Система →
  О программе → Дополнительные параметры системы → Переменные среды, или одной командой
  `setx TIDE_DIR "D:\Tibbo\TIDE"`; затем перезапустить агента.
- `TIBBO_BASIC_HOME` - папка компилятора Tibbo на Node.js (по умолчанию `~/.tibbo/tibbo-basic`); `TIBBO_BASIC_COMPILER` -
  путь к уже собранному `compile-project.js` или к папке репозитория tibbo-basic.
- `TIBBO_CLOUD_BUILD=yes` - согласие на облачную сборку для всех проектов (иначе - ключ `--cloud-ok` после вопроса).
- Облачная сборка ходит на `api.appblocks.io`. В облачной песочнице агента этот домен должен быть в списке разрешённых
  (в организации его добавляет администратор в настройках возможностей); в песочнице Codex нужна сеть
  (`[sandbox_workspace_write] network_access = true` в `config.toml`). Ошибка сертификата на Windows: `pip install truststore`.
- Ключ AppBlocks для сборки не нужен; если задан `APPBLOCKS_API_KEY`, он передаётся.

**Установка компилятора на Node.js** скачивает и запускает код с GitHub Tibbo (репозиторий tibbotech/tibbo-basic, ветка
`feature/compiler`, с платформами Tibbo) и пакеты npm: только после «да» пользователя (`--setup-node --yes`). Обновить -
та же команда.

**Правило согласия.** Облачная сборка отправляет весь проект на сервер Tibbo. Перед первой облачной сборкой в разговоре
спроси пользователя одной фразой («Собрать проект облачным компилятором Tibbo? Файлы проекта уйдут на сервер
AppBlocks.») и запускай с `--cloud-ok` только после «да». Если пользователь отказался - только `tibbo_lint.py`, и
честно напиши, что компиляции не было. Чужой проект (заказчика) без явного разрешения в облако не отправляй.

## 2. Проект TIDE (.tpr)

INI-файл; пробелы вокруг `=` допустимы (старые проекты пишут `platform = EM2000W`).

```ini
[project]
platform=TPP3W(G2)        ; точное имя платформы - папка в TIDE\Platforms
src_lib_ver=2_01_05       ; версия библиотек Tibbo: TIDE\Platforms\src\<версия>
output=app.tpc            ; имя результата
debug=on                  ; on - отладочный .tpc (ждёт TIDE), off - рабочий
defines= /dOBJECT_FD=FD_ENABLED   ; дополнительные #define проекта
transport=udp_broadcast   ; связь с устройством: udp_winpcap | udp_broadcast | serial (список - в Platforms\<платформа>\<платформа>.tp)
[address1]
address=0.36.119.87.32.2  ; адрес выбранного устройства (MAC в виде десятичных байт через точку)
[file1]
path=main.tbs             ; файл проекта
type=basic                ; basic | header | c | binary | xtext ...
location=                 ; пусто/без файла в папке - файл библиотеки из TIDE\Platforms\src\<src_lib_ver>
```

- Файлы библиотек подключаются двумя способами: копией в проекте (`libraries/sock/sock.tbs`, так делает AppBlocks) или
  путём внутрь TIDE (`sock\trunk\sock.tbs` при `src_lib_ver`). Облачный компилятор и `tmake` находят оба.
- В TIDE этого компьютера лежат версии библиотек 0_00 … 2_01_05; новые проекты - `2_01_05`.
- Файл, которого нет в `[fileN]`, в сборку не попадёт, даже если лежит в папке (кроме `include` из исходников).

## 3. Сборка

`tibbo_build.py` выбирает способ сам - по тому, **зачем** сборка:

| Зачем | Порядок | Почему |
|---|---|---|
| **Проверить код** (обычная сборка, без ключей) | компилятор Tibbo на Node.js → TIDE → облако | Node.js-компилятор быстрее и одинаков на любой ОС, код не покидает компьютер. |
| **Прошивка для устройства** (`--firmware`, `--release` или `--out`) | TIDE → компилятор на Node.js → облако | TIDE пользователя собирает с теми же платформами, что стоят у него и подходят к TiOS его устройств. Без TIDE скрипт пишет «Собрано для: TPP3W(G2)-4.02» - сверь с TiOS устройства. |
| **Проект на Tibbo C** | TIDE → облако | Компилятор на Node.js собирает только Tibbo BASIC. |

Способы:
- **Компилятор Tibbo на Node.js** (github.com/tibbotech/tibbo-basic, ветка `feature/compiler`) - перенос `tmake`/`tbc`/
  `tlink` Tibbo на Node.js, даёт тот же `.tpc`. Любая ОС, без TIDE, ставится один раз (`--setup-node --yes`).
- **TIDE на этом компьютере** (`tmake.exe`, Windows) - эталон, Tibbo BASIC и Tibbo C; кроме сборки - загрузка в
  устройство, отладка, Device Explorer, обновление TiOS (этого компилятор на Node.js не умеет).
- **Облачный компилятор Tibbo** - запасной: Tibbo C без TIDE и агенты, где Node.js-компилятор не поставить
  (нет Node.js или нет доступа к GitHub и npm). Только с согласия пользователя.

```text
python3 scripts/tibbo_build.py <папка проекта или .tpr>            # как задано в .tpr (debug on/off)
python3 scripts/tibbo_build.py <проект> --release --out app.tpc    # рабочая прошивка для устройства
python3 scripts/tibbo_build.py <проект> --firmware                 # прошивка как в .tpr (debug/release), сборка через TIDE
python3 scripts/tibbo_build.py <проект> --node                     # принудительно компилятор на Node.js
python3 scripts/tibbo_build.py <проект> --cloud --cloud-ok          # принудительно облако
python3 scripts/tibbo_build.py --setup-node --yes                   # поставить/обновить компилятор на Node.js
python3 scripts/tibbo_build.py <проект> --json                      # ошибки списком для разбора
```
Коды выхода: 0 - собрано, 1 - ошибки компилятора, 2 - неверный ввод, 3 - нет способа сборки или согласия, 4 - сеть.
`--release`/`--debug` не меняют проект пользователя: локально сборка идёт во временной копии.
Файлы в старой кодировке (cp1251, Big5 в комментариях) уходят в облако байт в байт, как их читает TIDE.
Проверка (ноябрь 2026): 15 проектов tibbotech (TPP2W/TPP3W G2 и G3, EM2000W, EM500W; Tibbo BASIC), каждый в debug и
release - компилятор на Node.js и облачный дали одинаковые `.tpc` (отличаются только код сборки, время и контрольная
сумма) и одинаковые ошибки с теми же строками. Компилятор на Node.js не пишет номер ошибки (`C1013`) - ищи по тексту.
Локальная (`tmake`) и загрузка (`tupload`) собраны по справке самих программ и **ещё не проверены на Windows**.

Командная строка TIDE (Windows), если нужно вызвать вручную:
```text
"%TIDE%\Bin\tmake.exe" project.tpr "-p%TIDE%\Platforms" "-b%TIDE%\Bin" -r      (запускать из папки проекта)
```
Ключи tmake (пишутся слитно с путём: `-pC:\...`): `-p` папка платформ (в ней `lib` и платформы), `-b` папка с `tbc.exe`/`tlink.exe` (обязательно: по умолчанию tmake ищет их в текущей папке), `-r` полная пересборка (Rebuild All), `-l` версия
библиотек вместо `src_lib_ver`, `-j` число потоков, `-w` без предупреждений, `-v` подробно, `-m` расход памяти.

**Debug и release.** Debug-`.tpc` после загрузки не запускается сам: ждёт команд TIDE (Run, шаги, точки останова).
Release-`.tpc` запускается сразу после загрузки и при каждом включении, отладка в нём выключена. Устройство «молчит»
после загрузки - первым делом проверь, не debug ли это.

**Предупреждения.** `C1006 preprocessor redefinition of 'OBJECT_FD'` и подобные из `Platforms\<платформа>\*.tph`
появляются, когда `defines=` проекта повторяет то, что уже задано платформой: безвредны. Остальные предупреждения читай.

## 4. Устройства: поиск, загрузка, запуск

Два инструмента:
- **TIDE на Windows** (`tupload.exe`) - через `tibbo_build.py --upload`. По сети и по COM-порту.
- **tide-proxy Tibbo на любой ОС** (github.com/tibbotech/tide-proxy, Node.js) - `scripts/tibbo_device.py`. Только по сети.
  Ставится один раз с согласия пользователя: `python3 scripts/tibbo_device.py --setup --yes` (около 100 МБ).
  **Экспериментально:** сделан по коду и описанию протокола tide-proxy, проверен на имитаторе протокола, на
  устройстве ещё нет. `tibbo_build.py --upload` без TIDE сам загружает через него.

```text
python3 scripts/tibbo_device.py list                                   # какие устройства Tibbo есть в сети
python3 scripts/tibbo_device.py buzz --mac 0.36.119.87.32.2            # пискнуть: «это какое устройство?»
python3 scripts/tibbo_device.py state --mac 0.36.119.87.32.2           # TiOS, программа, работает/остановлена
python3 scripts/tibbo_device.py upload app.tpc --mac <MAC> --yes [--run]
python3 scripts/tibbo_device.py run|stop|reboot --mac <MAC> --yes
python3 scripts/tibbo_build.py --upload app.tpc --target <MAC> --yes        # TIDE (tupload) или tide-proxy
python3 scripts/tibbo_build.py --upload app.tpc --target COM3 --serial --yes # по COM-порту, только TIDE
```
- Адрес - MAC устройства десятичными байтами через точку, как в `list`, в `address=` проекта и в Device Explorer.
- **Перед загрузкой, запуском, остановкой и перезагрузкой** спроси пользователя: какое устройство и что к нему
  подключено (программа останавливается, выходы - реле, двигатели - меняют состояние). Без `--yes` скрипты этого не
  делают. `list`, `state` и `buzz` безопасны.
- **Debug-сборка** после загрузки ждёт команды: `run` (или `upload ... --run`). Release запускается сама.
- **TiOS tide-proxy без разрешения не перепрошивает:** если устройство не входит в режим загрузки (в Loader или TiOS не
  подходит), скрипт останавливается. Перепрошить TiOS вместе с программой - `--allow-tios <tios-*.bin>`, только после
  «да» пользователя (файл - из `Platforms\<платформа>\firmware`).
- Нужно: компьютер в том же сегменте сети, что устройство (UDP broadcast, порт 65535; через роутер не найдёт),
  брандмауэр пропускает `node` по UDP. Облачная песочница агента сеть пользователя не видит - только агент на
  компьютере в этой сети. Проверка: `tibbo_device.py --doctor`.
- Вывод `sys.debugprint` пока только в TIDE: tide-proxy читает его по адресу из `.pdb`, а как этот адрес получить для
  TiOS, Tibbo не описала (вопрос отправлен).
- `tupload`: `--loader taiko.udpdevice|taiko.serialdevice --target <адрес> --app <файл>`, ещё `--no-build-id-check` и
  `--no-platform-version-check`. Загрузка через `tupload` из скилла **тоже пока не проверена на устройстве**: при первой
  загрузке попроси пользователя убедиться в результате (Device Explorer, поведение устройства).

## 5. Сообщения компилятора: причина и что делать

Формат: `файл(строка): error C1013: текст`. Номер строки - в файле из начала сообщения; ошибки в
`Platforms\...` обычно значат неверную платформу или `defines`. Исправляй **первую** ошибку и собирай заново:
следующие часто её следствие.

| Сообщение | Причина в Tibbo | Что делать |
|---|---|---|
| `'X' is not member of 'sock' object` (C1013) | Выдуманное или опечатанное свойство/метод объекта TiOS, или его нет на этой платформе. | `tibbo_lint.py --platform` подскажет похожее имя; сверить с tios-api.md. |
| `'X' is not member of 'T'` | Нет такого поля в структуре `type`. | Проверить объявление `type ... end type`. |
| `undeclared identifier 'X'` | Не подключён `.tbh` библиотеки, опечатка, константа не той платформы, нет `declare`. | `include` нужного заголовка, файл в `[fileN]` проекта, `PL_*` из platforms.md. |
| `identifier 'X' is not constant, variable, property or function` | Имя занято чем-то другим (тип, метка) или не объявлено. | Переименовать, проверить объявление. |
| `unable to find include file 'X'` | Файла нет в проекте или нет такой версии библиотек. | Добавить файл в проект / проверить `src_lib_ver` и путь. |
| `platform does not export 'X' syscall` | Функции нет на этой платформе (например, на G2 нет того, что есть на G3). | Другая функция или другая платформа; см. platforms.md. |
| `recursive calls are not supported` | Рекурсия (в т.ч. через цепочку процедур). | Переписать циклом или очередью. |
| `string capacity must not exceed 255` | `dim s as string(300)`. | Строка ≤ 255; длинные данные - буферы/массивы байт. |
| `type mismatch - unable to copy 'A' into 'B'` | Присваивание несовместимых типов (строка в число и т.п.). | Явное преобразование: `str()`, `val()`, `lval()`. |
| `type mismatch - unable to perform ... with 'X'` | Арифметика/сравнение с неподходящим типом. | Привести типы. |
| `argument count mismatch for 'X'` / `function 'X' does not take N arguments` | Не то число аргументов. | Сверить с объявлением или tios-api.md. |
| `function 'X' byref argument type mismatch` | В `byref` передан другой тип. | Передать переменную нужного типа. |
| `argument 'X' mismatches previous declaration` / `retval of function 'X' mismatches previous declaration` | `declare` и тело расходятся. | Синхронизировать `declare` и реализацию. |
| `function 'X' previously declared as subroutine, now is seen as function` (и наоборот) | `declare sub` vs `function`. | Привести к одному виду. |
| `functions must have return values` / `subroutines cannot have return values` | `function` без `as тип` или `sub` с `as тип`. | Исправить объявление. |
| `subroutines cannot be used in expressions` / `subroutine cannot be r-value` | `x = my_sub()`. | Сделать `function` или вызвать отдельно. |
| `event handlers cannot be called` | Прямой вызов `on_sock_event(...)` и т.п. | Вынести код в отдельную процедуру и вызывать её. |
| `'X' is already defined` / `redefinition of identifier 'X'` | Двойное объявление: две копии библиотеки, `dim` в .tbh без `#ifndef`, одинаковые имена. | Убрать дубликат; глобальные `dim` - в одном .tbs, в .tbh - `declare`. |
| `'X' already has body` | Процедура определена дважды (часто два одинаковых обработчика событий). | Объединить обработчики; библиотеки звать через `*_proc_*`. |
| `property 'X' is read-only` / `write-only` | Запись в свойство только для чтения (например, `sock.state`). | Нужен метод (`sock.connect`, `sock.close`). |
| `on the left of '=' there must be a variable or a property` | Присваивание константе или выражению. | Исправить левую часть. |
| `array index 'N' is out of bounds` | Индекс константой вне массива. | Проверить размер `dim a(N)` (индексы с 0). |
| `constant expression expected` / `constant numeric expression expected` | В размере массива/строки или `case` не константа. | `const`/`#define`. |
| `integer constant is too big` / `floating-point constant is too big` | Число вне диапазона типа. | Другой тип (`dword`, `real`). |
| `invalid expression (unexpected 'X')` / `'X' expected` / `identifier expected` | Синтаксис: незакрытая скобка, `elseif`, лишний символ. | Проверить строку выше; `else if` раздельно. |
| `newline in constant` | Незакрытая строка `"`. | Закрыть кавычку. |
| `matching '#endif' not found` / `unexpected '#endif'` | Непарные `#if/#endif`. | Проверить препроцессор. |
| `preprocessor loop detected` / `include depth limit exceeded` | Взаимные `include`. | Защитные `#ifndef` или убрать цикл. |
| `division or modulo by zero` | Деление на константу 0. | Исправить выражение. |
| Компоновщик: `Compiled binary file is too large to fit on currently selected target` | Программа больше ROM платформы. | Убрать неиспользуемые библиотеки, ресурсы, вывод отладки; платформа с большей памятью. |
| Компоновщик: `Your project requires more variable memory (RAM) than available` | Глобальные переменные не влезают в RAM. | Уменьшить массивы и строки (`string(32)` вместо 255), буферы; см. память платформы в platforms.md. |
| `Unable to find library 'X'` | Нет версии библиотек `src_lib_ver` в этом TIDE. | Указать установленную версию (`-l` или правка `.tpr`). |

Полный список текстов сообщений взят из компилятора TIDE (`tbc.exe`); номера `C####` компилятор ставит сам.

## 6. Работа в окне TIDE

Названия - как в TIDE и на docs.tibbo.com (guide_tide_compiling, ref_tide_dialogs_dex, ref_tide_dialogs_project_settings).
1. **Выбрать устройство:** Debug > Select/Manage Target (или File > Project Settings → Select) → щёлкнуть устройство →
   **Select** (отметится прицелом). Не видно - **Refresh**; устройство должно быть в том же сегменте сети: через
   роутер TIDE его не найдёт, через коммутатор - найдёт.
2. **Настройки проекта:** File > Project Settings - Platform, Transport (Tibbo советует WinPCap UDP Transport; WinPcap
   лежит в TIDE\Bin), Build mode (Debug/Release), Source library set (версия библиотек).
3. **Собрать:** Build > Rebuild All - ошибки в панели Output, двойной щелчок ведёт к строке.
4. **Запустить с отладкой:** Debug > Run (F5) - сохранить, собрать, загрузить и запустить; пауза, шаги, точки
   останова, Watch.
5. **Рабочая прошивка:** Build mode = Release (выпадающий список на панели Debug или Project Settings) →
   Build > Rebuild All and Upload. Программа стартует сама после загрузки и при каждом включении.
6. **TiOS устройства** (`.tpc` её не содержит): Device Explorer → Upload... → Load Firmware Through the Network (или
   Through the Serial Port (X-modem), если устройство не отвечает по сети). Файл TiOS для платформы - в
   `TIDE\Platforms\<платформа>\firmware\tios-*.bin`.
7. Прошивка вместе с TiOS одним файлом для производства - docs.tibbo.com/guide_tide_releasing.

Агенту с управлением компьютером: сначала собери `tibbo_build.py` (быстро, текстом), в окно TIDE переходи для загрузки,
отладки и того, чего нет в командной строке. Любую загрузку в устройство - только после «да» пользователя.

## 7. Инструкция пользователю под его случай

Пользователь спрашивает, как что-то сделать в TIDE, просит «проверить на железе», или работа дошла до устройства -
дай **его** инструкцию, а не общую справку.

1. Собери факты: `python3 scripts/tibbo_build.py --doctor <папка проекта>` (с `--json` - для разбора). Он сообщает:
   где работает агент, есть ли TIDE и его версию, платформы и версии библиотек в нём, TiOS для платформы проекта,
   WinPcap, выбранное в проекте устройство, debug или release, свои платформы проекта - и печатает
   **«Рекомендации по TIDE для этого проекта»**. Скрипт запустить нельзя - спроси одним сообщением: платформа, версия
   TIDE (если знает), устройство в сети или на COM-порту, что нужно сделать.
2. Определи цель: собрать и найти ошибки / отладить на устройстве / поставить рабочую прошивку / обновить TiOS /
   прошить несколько устройств / подготовить к производству.
3. Напиши инструкцию: нумерованные шаги, точные пункты меню из §6, имена файлов и путей **из фактов** (платформа,
   файл TiOS, версия библиотек, адрес устройства). Сначала - что мешает (рекомендации `--doctor`), потом сама задача,
   в конце - как понять, что получилось (что появится в Output, как поведёт себя устройство).
4. Раздели, кто что делает: что агент сделает сам (сборка, разбор ошибок, загрузка после «да»), а что только
   пользователь (выбор устройства в Device Explorer, обновление TiOS, отладка по шагам, установка WinPcap, настройки
   агента из §1).
5. Не выдумывай: пункта меню нет в §6 - так и скажи и дай ссылку на docs.tibbo.com. Опасные шаги (обновление TiOS,
   смена MAC, загрузка в работающее оборудование) - с предупреждением, что будет с устройством.

Типовые случаи и что обязательно сказать:

| Случай | Главное в инструкции |
|---|---|
| TIDE нет, Windows | Скачать TIDE на tibbo.com (Downloads), установить; первая проверка - `--doctor`. До установки - облачная сборка с согласия. |
| Платформы проекта нет в TIDE | Обновить TIDE или выбрать платформу своего устройства в File > Project Settings → Platform. |
| Нет версии библиотек проекта | Source library set → установленная версия, пересобрать, сверить вызовы библиотек (libraries.md). |
| Debug-сборка «не работает» на устройстве | Она ждёт Debug > Run (F5); для работы без компьютера - Release и Rebuild All and Upload. |
| Устройство не находится | Тот же сегмент сети, Refresh, брандмауэр для tide.exe/tdevexplore.exe, WinPcap при Transport = WinPCap; последний шаг - X-modem через COM-порт. |
| TIDE пишет о несовпадении версий TiOS | Обновить TiOS файлом из `Platforms\<платформа>\firmware` (Upload... → Load Firmware Through the Network); предупредить, что приложение на устройстве после этого нужно загрузить заново. |
| Несколько устройств одной прошивкой | Собрать release (`tibbo_build.py --release --out app.tpc`), загружать по одному: `--upload app.tpc --target <адрес> --yes` или Device Explorer → Upload... → Load Application Through the Network. |
| Производство | Прошивка с TiOS одним файлом - docs.tibbo.com/guide_tide_releasing; агент даёт ссылку и порядок, сам не прошивает. |
